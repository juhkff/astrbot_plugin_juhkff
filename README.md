# 综合插件

提供主动群聊、分享卡片解析、偷表情、日报、Pixiv 画师订阅和帮助图，支持按功能独立开关。

功能参考 [juhkff-plugin](https://github.com/juhkff/juhkff-plugin)。

## 安装

1. 在 AstrBot WebUI 的插件管理中，通过[本仓库地址](https://github.com/juhkff/astrbot_plugin_juhkff)安装插件。
2. 在 **AstrBot 使用的 Python 环境**中安装依赖和 Chromium。以下命令从 AstrBot 根目录执行：

   ```bash
   python -m pip install -r data/plugins/astrbot_plugin_juhkff/requirements.txt
   python -m playwright install chromium
   ```

3. 重启或重载插件，在「插件管理 → 综合插件 → 设置」中配置接收群及各功能开关；对话模型、人设和回复规则在 AstrBot 官方配置中设置。

日报和帮助图使用本机 Chromium 渲染，Linux 需要中文字体，安装方法见下方。

## 常用指令

以下为默认写法，命令前缀以 AstrBot 配置为准。日报和 Pixiv 指令在群聊中使用。

| 指令 | 用途 |
| --- | --- |
| `/juhkff` | 查看插件状态 |
| `#帮助` | 查看本插件已启用功能的帮助，可在设置中修改触发词 |
| `#日报` | 获取今日日报 |
| `#pixiv订阅 UID` | 当前群订阅指定画师，例如 `#pixiv订阅 123456` |
| `#pixiv取消订阅 UID` | 当前群取消该画师订阅，不影响其他群 |

卡片解析和偷表情自动处理群消息，无需指令。卡片解析支持 B 站、小黑盒等分享卡片，不处理普通文字链接。

## 配置要点

主动群聊默认关闭，其他功能默认启用；完整选项及说明以 WebUI 设置页为准。

**主动群聊（默认关闭）**

在「综合插件 → 设置 → 主动群聊」启用，通过框架会话选择器选择生效群，可多选，也可手动填写群号或完整会话 ID；留空应用于所有群。在本页的「框架运行设置」中选择对话模型、回退模型、人格和知识库，配置联网搜索、流式输出、工具调用，无需再到框架配置中重复设置这些群聊选项。推荐在「插件管理 → 显示系统插件」中禁用官方 `astrbot`，由本模块处理群聊触发和 Redis 上下文，执行继续复用核心 Agent。

模型账户、人格内容和知识库资源仍由框架统一创建和管理，插件使用已有选择器选择它们。对话模型留空时按核心规则使用第一个已注册模型，人格默认为 `default`；选择具体模型和人格即可固定本模块的配置。基础 Agent 执行器需为内置 Agent（AstrBot 默认），不支持将已初始化的第三方 Agent 管线切换为内置管线。禁用 `astrbot` 系统插件不会禁用核心 Agent，也不需要开启官方主动回复或群消息注入。

「框架运行设置」是本模块群聊的权威配置：其中的新选项使用框架默认值，不自动导入框架已有的自定义值。联网搜索在本页开启并填写对应提供商凭据即可；本次消息即使遇到框架总配置关闭模型或设置额外模型唤醒前缀，也由插件接话策略安排。覆盖只写当前群消息的独立快照，不保存全局配置，不影响其他群、私聊或注册命令；图片模式及转述模型仍由上方图片设置控制。平台连接及不支持原生流式的平台适配策略沿用框架设置。每次获准回复时按该快照初始化核心 Agent 阶段，让流式、工具结果和推理显示等选项生效；不替换共享管线。

需运行可连接的 Redis 服务，并在本模块设置连接地址（默认 `redis://localhost:6379/0`）和独立键前缀。安装依赖后重载插件即可；不要将 Redis 密码贴到群聊中。多个 AstrBot 实例必须使用不同键前缀。

- 普通群消息逐条独立以默认 20% 概率接话，没有接话冷却；旧配置里的 `cooldown` 不再使用。概率为 0 时只保留核心识别的 @、唤醒词等唤醒回复；识别来自框架核心，接话和上下文由本模块负责，不需要启用官方 `astrbot` 插件。不是语义判断，也不会在无人发言时定时开话题。
- 纯 @（含前后空白）直接承接近期前文，不再触发官方的“询问来意并等待下一条消息”分支；没有相关前文时由模型简短询问。首次纯 @ 会自动建立官方对话，普通消息的主动接话也复用可自动建立对话的核心输入流程。
- 群友消息和机器人回复统一存入 Redis，默认每会话保留最近 40 条消息；保留发送者 ID、昵称、时间、@ 和引用信息，每条最多 2000 字符。按官方会话标识隔离，不按时间过期；超过配置条数上限时移除最旧记录。
- 上下文采用消息到达时的原子快照，不因开始请求就清空。Redis 历史按记录顺序平铺为多轮消息：群友使用 `role=user`，本机器人已发送的回复使用 `role=assistant`；保留连续的群友发言，当前输入只放在末尾一次，不再拼接群聊背景块。每条消息保留发言人信息，原图跟随所属消息，引用图片另标原作者，无法获得原作者时标为未知。
- 新消息以结构化记录保存角色、发送者和时间；热重载可读取旧版文字和图片记录，无需清空 Redis。每轮仅使用 Redis 历史，不加载官方数据库旧对话或人格预设对话，并移除读取旧群消息数据库的 `get_group_message_history` 工具。历史以临时消息参与模型请求和本轮工具循环，不重复写入官方对话；人格系统提示词保持原样，不自动添加“只回复最新消息”等规则。数据库可继续展示本轮对话，但不会作为后续群聊上下文重新输入。
- AstrBot 重启与插件热重载均保留 Redis 历史；连接时会取消本模块现存旧消息键的过期时间，已过期删除的数据无法恢复。历史仅在超过条数上限时滚动移除，或由用户删除、重置。Redis 服务自身需配置持久化才能保证其重启后保留数据；插件不修改 Redis 服务配置。`/reset`、`/new` 成功后清理对应会话记录；这些命令需要另外启用 `builtin_commands`，它与官方 `astrbot` 是两个插件。
- Redis 不可用时，不改用内存或旧数据库历史；本次仍可基于当前消息回复，但缺少群聊背景。初次连接失败后至少等待 30 秒再重连，日志会记录失败。
- 注册命令与本插件指令优先；其他处理器已经停止事件、发过消息或安排模型请求时，本模块不再发起一次回复。
- **原图模式（默认）**：Redis 保留当前和历史图片的原始 URL/base64；回复时将历史图片按发送者和消息顺序注入，本轮图片继续走核心媒体处理。需要支持图片的聊天模型；当前模型不支持时尝试配置中的视觉备用模型，没有可用视觉模型则跳过该轮并记录错误。
- **文字模式**：接管范围内的非命令群消息只要含图片，就在接话判断之前转述；没有抽中回复也会处理并保存。设置页仅在选择「文字模式」后显示「文字模式设置」，其中「判断是否为表情包」（`caption_settings.detect_meme`）默认开启。开启后一次视觉调用同时生成逐图 `is_meme` 判断和描述：表情包说明画面、文字及表达的情绪或梗，普通图片描述可见内容和关键信息；关闭后只转述内容，不请求分类、不生成分类标签或保存分类字段。不因分类自动触发或禁止回复，也不改变独立偷表情模块。开启时无法可靠解析分类则记为未知并保留可用描述；开关不改写已保存的历史描述和分类。
- 成功的图片描述（历史展示最多 2000 字符）及开启判断时生成的逐图分类 `image_analysis` 保存在原 Redis 消息记录中，与原始图片引用并存。后续文字模式使用原文和描述、跳过原图；切回原图模式使用原图，不额外注入描述。转述失败和以前未保存描述的旧记录不补做历史转述；仍保留原文和原图。描述按原消息 ID 更新，不新增记录，也不恢复已被清理的记录。
- 两种模式均保存图片原始引用：网络 URL 和已有 base64 原样保留；仅有本地文件时转成 base64，避免临时文件清理后历史图片失效。2000 字符限制只作用于消息文字，不截断图片数据。图片 URL 本身过期后仍可能无法读取。
- 「文字模式设置 → 图片转述模型」（`caption_settings.provider_id`）复用 AstrBot 的模型选择器，从已配置模型中选择支持图片的转述模型；留空兼容旧版 `image_caption_provider_id`，之后依次使用核心默认图片转述模型和当前聊天模型。本模块在当前消息独立配置快照中关闭核心的默认图片转述，统一由本模块控制模式，不修改全局配置。引用、卡片文字格式和其他媒体处理仍复用核心能力。

官方 `astrbot` 禁用时，本模块照常工作，使用其中的消息格式化类不需要启用其事件处理器。如仍启用官方 `astrbot`，本模块也会在生效群跳过其 `handle_empty_mention` 和 `on_message`，防止双重触发。未指定的群和私聊不注入本模块背景；官方插件禁用后，这些群也不会获得官方主动接话和群聊背景注入。插件不自动修改官方配置、停用名单或历史数据库。

此处依赖当前 AstrBot 内部处理器名称及优先级，基于 AstrBot v4.29.4 验证，升级框架时需要回归验证。建议先只填写测试群，将概率临时设为 1，验证“天气如何 → 单独 @”及普通接话，再恢复期望值。人格在 AstrBot 官方人格设定中编辑，本模块不指定名字或另设人格。

**非接管群聊及私聊**：仍使用对应的 AstrBot 配置，包括模型、人格、工具及联网搜索。

**偷表情**

- 同群相同图片在默认 72 小时内第二次出现时收藏，默认单图不超过 2 MB，每群最多 30 张。
- 发图优先使用本群收藏，没有可用收藏时使用配置的本地表情包文件夹。发图概率设为 0 仍会收藏。
- 表情判断需同时开启开关并选择支持图片输入的模型；未选模型或判断失败时，按重复规则收藏。

**日报**

- 包含时政、国内社会、游戏、数码四类新闻，每类最多 12 条；提供五款样式，可固定或每次随机选择。
- 自动推送需选择接收群并设置时间；接收群为空时不自动发送。「提前生成」可单独开启，减少发送时等待。
- 图片按日期和样式缓存；样式仅在设置页选择，获取指令统一为 `#日报`。

**Pixiv 订阅**

- UID 是画师主页的数字用户 ID。群内订阅指令会同步到设置页的「画师订阅列表」，也可直接在设置页编辑接收群。
- 默认每 60 分钟检查一次，补齐两次检查间的全部新插画及全部分页；同一画师本轮新作合并为一条转发消息，接收平台需支持合并转发（如 QQ/NapCat）。
- 首次订阅及 AstrBot 进程重启后，只以最新作品建立基线，不补推旧作或停机积压；订阅配置保留。热重载保留进度，部分群失败只补发未收到的作品。
- 默认原图优先、不压缩；可设置正数压缩阈值。单张下载另有 **64 MiB 安全上限**，并非 QQ 大小限制。
- 获取作品、下载或发送失败时，默认依次等待 2、4、6…分钟；基础间隔可调，成功后恢复正常检查。任务按分钟调度，实际可能略晚。
- 无需登录，只订阅插画，不包含漫画、小说，也不提供 R18 筛选。

**全局设置**：网络代理填写 HTTP 地址，例如 `http://127.0.0.1:7890`；时区默认 `Asia/Shanghai`。详细日志默认开启，可按需关闭。

## 常见问题

### 日报或帮助图的中文显示为方框

在 **AstrBot 实际运行的系统或容器**中安装中文字体，按系统选择命令。

Ubuntu / Debian：

```bash
sudo apt-get update
sudo apt-get install -y fontconfig fonts-noto-cjk
```

Rocky / AlmaLinux / RHEL 8、9 等 dnf 系统：

```bash
sudo dnf install -y fontconfig google-noto-sans-cjk-ttc-fonts google-noto-serif-cjk-ttc-fonts
```

刷新并确认字体：

```bash
sudo fc-cache -f
fc-list :lang=zh family
```

应能看到 Noto Sans CJK 和 Noto Serif CJK。其他 dnf 发行版的包名可能不同，可用 `dnf list --available '*noto*cjk*'` 查询。

安装后重启 AstrBot。日报还需备份移走 `data/plugin_data/astrbot_plugin_juhkff/daily_report/YYYY-MM-DD/` 下当天的五张样式 PNG，再发送 `#日报`；保留新闻快照和配图即可。帮助图每次重新生成，无需清理。

### 设置代理后仍无法访问 Pixiv

- 代理必须能被 AstrBot 所在环境访问。Docker 中的 `127.0.0.1` 指向容器自身；仅提供 SOCKS5 的地址不能直接使用。
- 插件代理用于网页和图片请求，模型 API、QQ 连接按各自配置处理。
- 本机 DNS 仍需返回真实公网地址；代理的 Fake-IP 模式可能被安全校验拒绝。网络请求仅允许公网 HTTP(S) 的 80/443 端口。

### 数据保存在哪里

- 订阅等设置：`data/config/astrbot_plugin_juhkff_config.json`。
- 表情、日报和 Pixiv 缓存：`data/plugin_data/astrbot_plugin_juhkff/`。备份迁移时可一并保留该目录和配置文件。

## 开发与测试

在已安装依赖的 AstrBot Python 环境中，从 **AstrBot 根目录**执行：

```bash
PYTHONPATH=.:data/plugins/astrbot_plugin_juhkff \
  python -m unittest discover -s data/plugins/astrbot_plugin_juhkff/tests -p 'test_*.py'
PYTHONPATH=. python data/plugins/astrbot_plugin_juhkff/tests/check_command_routing.py
```

第二条独立运行，以隔离插件入口的热重载注册。测试覆盖网络安全、卡片、表情、渲染、缓存、Pixiv 状态及命令分发，不调用真实模型或发送群消息。
