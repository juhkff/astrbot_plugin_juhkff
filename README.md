# 综合插件

提供主动群聊、分享卡片解析、偷表情、日报、Pixiv 画师订阅与榜单浏览、随机取图、作品点图和帮助图，支持按功能独立开关。

功能参考 [juhkff-plugin](https://github.com/juhkff/juhkff-plugin)。

## 安装

1. 在 AstrBot WebUI 的插件管理中，通过[本仓库地址](https://github.com/juhkff/astrbot_plugin_juhkff)安装插件。
2. 在 **AstrBot 使用的 Python 环境**中安装依赖和 Chromium。以下命令从 AstrBot 根目录执行：

   ```bash
   python -m pip install -r data/plugins/astrbot_plugin_juhkff/requirements.txt
   python -m playwright install chromium
   ```

3. 重启或重载插件，在「插件管理 → 综合插件 → 设置」中配置接收群及各功能开关；对话模型、人设和回复规则在 AstrBot 官方配置中设置。

插件在首次加载及每次重载时自动启动已启用模块、注册定时任务，无需先发送消息。修改日榜等定时设置后重载插件即可生效；日榜按下一次设定时刻执行，已错过的时间不补发。

日报和帮助图使用本机 Chromium 渲染，Linux 需要中文字体，安装方法见下方。

## 常用指令

以下为默认写法，命令前缀以 AstrBot 配置为准。日报和 Pixiv 指令在群聊中使用。

| 指令 | 用途 |
| --- | --- |
| `/juhkff` | 查看插件状态 |
| `#帮助` | 查看本插件已启用功能的帮助，可在设置中修改触发词 |
| `#日报` | 获取今日日报 |
| `#pixiv订阅 UID` | 当前群订阅指定画师，例如 `#pixiv订阅 123456` |
| `#pixiv取消订阅 UID` | 当前群取消该画师订阅，不影响其他群 |
| `#pixiv日榜` / `#pixiv周榜` / `#pixiv月榜` | 获取对应榜单，数量在设置页配置，命令不接收数量参数 |
| `#pixiv随机 [关键词/标签]` | 无词时从多页日榜候选池随机取图；有词时从搜索结果随机取图 |
| `#pixiv作品 ID或URL [第N张]` | 按作品 ID 或作品链接取图，默认全部分页；如 `#pixiv作品 123456 第2张` |

卡片解析和偷表情自动处理群消息，无需指令。卡片解析支持 B 站、小黑盒等分享卡片，不处理普通文字链接。

## 配置要点

主动群聊默认关闭，其他功能模块默认启用；Pixiv 日榜自动推送、榜单变动监测和随机发图默认关闭。完整选项及说明以 WebUI 设置页为准。

每个功能配置下都有独立的「打印日志」（`print_log`），默认开启。关闭后，该功能的运行信息、DEBUG、警告、错误和异常堆栈均不输出；共享渲染器、日报来源采集、状态读取和定时任务日志跟随所属功能。群聊请求内容也由主动群聊的此开关控制。已移除全局「详细日志」，旧 `global.debug` 不再生效；开启时仍按框架日志等级筛选，关闭时不会降为 DEBUG 继续输出。框架核心及其他插件自身的日志仍由它们管理。

**主动群聊（默认关闭）**

在「综合插件 → 设置 → 主动群聊」启用，通过框架会话选择器选择生效群，可多选，也可手动填写群号或完整会话 ID；留空应用于所有群。在本页直接选择对话模型、回退模型、人格和知识库，配置联网搜索、流式输出、工具调用，无需再到框架配置中重复设置这些群聊选项。推荐在「插件管理 → 显示系统插件」中禁用官方 `astrbot`，由本模块处理群聊触发和 Redis 上下文，执行继续复用核心 Agent。

模型账户、人格内容和知识库资源仍由框架统一创建和管理，插件使用已有选择器选择它们。对话模型留空时按核心规则使用第一个已注册模型，人格默认为 `default`；选择具体模型和人格即可固定本模块的配置。基础 Agent 执行器需为内置 Agent（AstrBot 默认），不支持将已初始化的第三方 Agent 管线切换为内置管线。禁用 `astrbot` 系统插件不会禁用核心 Agent，也不需要开启官方主动回复或群消息注入。

「主动群聊」下直接展示「模型与人格」「联网搜索」「回复展示」「工具调用」「知识库」「输入与附件」六组，不再套「框架运行设置」或内置 Agent 等中间层。升级后自动迁移两代旧布局的插件运行配置，保留已选择的模型、人格、搜索凭据及其他选项，无需重新填写；新建配置仍使用框架默认值。这些设置是本模块群聊的权威配置，不自动导入框架已有的自定义值。联网搜索在本页开启并填写对应提供商凭据即可；本次消息即使遇到框架总配置关闭模型或设置额外模型唤醒前缀，也由插件接话策略安排。覆盖只写当前群消息的独立快照，不保存全局配置，不影响其他群、私聊或注册命令；图片模式及转述模型仍由上方图片设置控制。平台连接及不支持原生流式的平台适配策略沿用框架设置。每次获准回复时按该快照初始化核心 Agent 阶段，让流式、工具结果和推理显示等选项生效；不替换共享管线。

需运行可连接的 Redis 服务，并在本模块设置连接地址（默认 `redis://localhost:6379/0`）和独立键前缀。安装依赖后重载插件即可；不要将 Redis 密码贴到群聊中。多个 AstrBot 实例必须使用不同键前缀。

- 普通群消息逐条独立以默认 20% 概率接话；可在「分群接话概率」中添加规则，通过群选择器为一个或多个群设置单独概率，也支持填写群号或完整会话 ID。未匹配规则的群沿用默认概率，同群匹配多条规则时使用第一条，适用群留空的规则不生效；分群规则不会扩大上方「生效群列表」的范围。没有接话冷却；旧配置里的 `cooldown` 不再使用。概率为 0 时只保留核心识别的 @、唤醒词等唤醒回复；识别来自框架核心，接话和上下文由本模块负责，不需要启用官方 `astrbot` 插件。不是语义判断，也不会在无人发言时定时开话题。
- 纯 @（含前后空白）直接承接近期前文，不再触发官方的“询问来意并等待下一条消息”分支；没有相关前文时由模型简短询问。首次纯 @ 会自动建立官方对话，普通消息的主动接话也复用可自动建立对话的核心输入流程。
- 群友消息和机器人回复统一存入 Redis，默认每会话保留最近 40 条消息；保留发送者 ID、昵称、时间、@ 和引用信息，每条最多 2000 字符。按官方会话标识隔离，不按时间过期；超过配置条数上限时移除最旧记录。
- 上下文采用消息到达时的原子快照，不因开始请求就清空。Redis 历史按记录顺序平铺为多轮消息：群友使用 `role=user`，本机器人已发送的回复使用 `role=assistant`；保留连续的群友发言，当前输入只放在末尾一次，不再拼接群聊背景块。每条消息保留发言人信息，原图跟随所属消息，引用图片另标原作者，无法获得原作者时标为未知。
- 新消息以结构化记录保存角色、发送者和时间；热重载可读取旧版文字和图片记录，无需清空 Redis。每轮仅使用 Redis 历史，不加载官方数据库旧对话或人格预设对话，并移除读取旧群消息数据库的 `get_group_message_history` 工具。历史以临时消息参与模型请求和本轮工具循环，不重复写入官方对话；人格系统提示词保持原样，不自动添加“只回复最新消息”等规则。数据库可继续展示本轮对话，但不会作为后续群聊上下文重新输入。
- AstrBot 重启与插件热重载均保留 Redis 历史；连接时会取消本模块现存旧消息键的过期时间，已过期删除的数据无法恢复。历史仅在超过条数上限时滚动移除，或由用户删除、重置。Redis 服务自身需配置持久化才能保证其重启后保留数据；插件不修改 Redis 服务配置。`/reset`、`/new` 成功后清理对应会话记录；这些命令需要另外启用 `builtin_commands`，它与官方 `astrbot` 是两个插件。
- Redis 不可用时，不改用内存或旧数据库历史；本次仍可基于当前消息回复，但缺少群聊背景。初次连接失败后至少等待 30 秒再重连，日志会记录失败。
- 注册命令与本插件指令优先；其他处理器已经停止事件、发过消息或安排模型请求时，本模块不再发起一次回复。
- 开启「主动群聊 → 打印日志」后，以 INFO 级别输出 `[juhkff] LLM request body:`。日志按 `system：`、`user：`、`assistant：`、`tool：` 分段换行显示，保留正文换行、消息顺序、工具调用和结果；会话、消息 ID、接口路径、模型和参数另行展示；`tools` 仅列出工具名称，省略说明和参数定义，实际工具调用及结果仍完整展示。消息中的 `reasoning_content` 为空时隐藏，有内容时按 `reasoning：` 单独换行展示。图片用 URL 或 MIME 类型与 base64 长度标记，不打印 base64 长串。展示基于实际发送的 JSON，不改变请求内容。支持 OpenAI / OpenAI Responses、Anthropic、Gemini 的 HTTPX 客户端，图片转述和工具后续请求分别记录。关闭打印日志后不输出请求体，即使框架日志等级为 DEBUG。仅记录本模块接管消息作用域内的请求，不记录 HTTP 请求头和 URL 查询参数；其他客户端暂不支持。
- **原图模式（默认）**：Redis 保留当前和历史图片的原始 URL/base64；回复时将历史图片按发送者和消息顺序注入，本轮图片继续走核心媒体处理。需要支持图片的聊天模型；当前模型不支持时尝试配置中的视觉备用模型，没有可用视觉模型则跳过该轮并记录错误。
- **文字模式**：接管范围内的非命令群消息只要含图片，就在接话判断之前转述；没有抽中回复也会处理并保存。设置页仅在选择「文字模式」后显示「文字模式设置」，其中「判断是否为表情包」（`caption_settings.detect_meme`）默认开启。开启后一次视觉调用同时生成逐图 `is_meme` 判断和描述：表情包说明画面、文字及表达的情绪或梗，普通图片描述可见内容和关键信息；关闭后只转述内容，不请求分类、不生成分类标签或保存分类字段。不因分类自动触发或禁止回复，也不改变独立偷表情模块。开启时无法可靠解析分类则记为未知并保留可用描述；开关不改写已保存的历史描述和分类。
- 成功的图片描述（历史展示最多 2000 字符）及开启判断时生成的逐图分类 `image_analysis` 保存在原 Redis 消息记录中，与原始图片引用并存。后续文字模式使用原文和描述、跳过原图；切回原图模式使用原图，不额外注入描述。转述失败和以前未保存描述的旧记录不补做历史转述；仍保留原文和原图。描述按原消息 ID 更新，不新增记录，也不恢复已被清理的记录。
- 两种模式均保存图片原始引用：网络 URL 和已有 base64 原样保留；仅有本地文件时转成 base64，避免临时文件清理后历史图片失效。2000 字符限制只作用于消息文字，不截断图片数据。图片 URL 本身过期后仍可能无法读取。
- 「文字模式设置 → 图片转述模型」（`caption_settings.provider_id`）复用 AstrBot 的模型选择器，从已配置模型中选择支持图片的转述模型；留空兼容旧版 `image_caption_provider_id`，之后依次使用核心默认图片转述模型和当前聊天模型。本模块在当前消息独立配置快照中关闭核心的默认图片转述，统一由本模块控制模式，不修改全局配置。引用、卡片文字格式和其他媒体处理仍复用核心能力。

官方 `astrbot` 禁用时，本模块照常工作，使用其中的消息格式化类不需要启用其事件处理器。如仍启用官方 `astrbot`，本模块也会在生效群跳过其 `handle_empty_mention` 和 `on_message`，防止双重触发。未指定的群和私聊不注入本模块背景；官方插件禁用后，这些群也不会获得官方主动接话和群聊背景注入。插件不自动修改官方配置、停用名单或历史数据库。

此处依赖当前 AstrBot 内部处理器名称及优先级，基于 AstrBot v4.29.4 验证，升级框架时需要回归验证。建议先只填写测试群，将概率临时设为 1，验证“天气如何 → 单独 @”及普通接话，再恢复期望值。人格在 AstrBot 官方人格设定中编辑，本模块不指定名字或另设人格。

**非接管群聊及私聊**：仍使用对应的 AstrBot 配置，包括模型、人格、工具及联网搜索。

**偷表情**

- 同群相同图片在默认 72 小时内第二次出现时收藏，默认单图不超过 2 MB，每群最多 30 张。
- 发图优先使用本群收藏，没有可用收藏时使用配置的本地表情包文件夹。发图概率设为 0 仍会收藏。
- 表情判断需同时开启开关并选择支持图片输入的模型；未选模型或判断失败时，按重复规则收藏。

**日报**

- 包含时政、国内社会、游戏、数码四类新闻，每类最多 12 条；提供五款样式，可固定或每次随机选择。
- 自动推送需选择接收群并设置时间；接收群为空时不自动发送。「提前生成」可单独开启，减少发送时等待。
- 图片按日期和样式缓存；样式仅在设置页选择，获取指令统一为 `#日报`。

**Pixiv 订阅与浏览**

- 「支持命令无pixiv前缀」（`allow_prefixless`）默认开启：`#订阅 UID`、`#取消订阅 UID`、`日榜`、`周榜`、`月榜`、`随机 [关键词]`、`作品 ID或链接 [第N张]` 均可使用；简写可带 `#`、`/`，也可直接发送，无需 @。关闭后仅保留原有 `pixiv…` 命令。只匹配命令及参数，不匹配“日榜真好看”等普通句子；同名框架注册命令仍优先。帮助菜单随开关展示简写。

- 帮助图和文字回退均列出已启用模块的命令及自动功能，包含帮助命令本身、`/juhkff` 状态命令、主动群聊、可选定时日报和 Pixiv 日榜。

- Pixiv 支持 AI 语义工具调用：`juhkff_pixiv_ranking` 获取日／周／月榜，`juhkff_pixiv_random` 随机取图或按关键词取图，`juhkff_pixiv_artwork` 按作品 ID／链接点图并可选择页码。重载插件后，在 AstrBot 的工具管理中确认这三个工具已启用，并使用支持工具调用的聊天模型。群聊中唤醒 AI 后，可以说“看看今天的 Pixiv 榜单”“找一张风景插画”“把这个 Pixiv 链接的第二张发来”，由模型决定是否调用；仅在回复中写出指令不会自动执行。工具在插件加载时注册，关闭 Pixiv 功能只会阻止执行，不会自动从模型工具列表中移除；若不希望模型看到这些工具，可在 AstrBot 工具管理中禁用它们。
- 语义取图与手动指令共用校验、作品数量、缓存、翻译和当前群内容规则，只向发起请求的群发送，未提供订阅或配置修改工具。随机工具沿用手动随机入口；最近 200 条历史及补取机制仍用于自动随机推送和榜单监测。模型或模型服务自身的内容限制不受 Pixiv R18 开关控制。多页图片翻译还受 AstrBot 的「工具调用超时时间（秒）」约束（`agent.config.misc.tool_call_timeout`），需要结合实际下载、翻译耗时设置；单页翻译超时不等于整个工具的总超时。工具只在实际发送成功后报告已发送；发送报错或超时不自动重发。
- UID 是画师主页的数字用户 ID。群内订阅指令会同步到设置页的「画师订阅列表」，也可直接通过会话选择器编辑接收群。默认每 60 分钟检查一次，补齐两次检查间的全部新插画及全部分页。
- 首次订阅及 AstrBot 进程重启后，只以最新作品建立基线，不补推旧作或停机积压；订阅配置保留。热重载保留进度，部分群失败只补发未收到的作品。画师订阅只检查插画，不包含漫画、小说。
- `#pixiv日榜`、`#pixiv周榜`、`#pixiv月榜` 获取对应榜单，每篇作品展示全部分页，并附原始排名、标题、画师与作品链接。`ranking.count` 默认 3，范围 1～20；数量按作品数计算，不限制单篇分页数量；仅在设置页配置，命令不接收数量参数。目标群关闭 R18 过滤时，日榜、周榜同时读取全年龄榜及对应 R18 榜，每个榜分别取最多 `ranking.count` 部作品，保留各自排名；按「全年龄 → `---------------- NSFW ----------------` → R18」放在同一条合并转发内，两类内容同时存在时不单独发送分割线。R18 沿用该群原图／链接展示规则，需要有效 Pixiv 登录态；R18 榜读取失败时仍可发送全年龄榜。月榜没有对应的 R18 模式，保持全年龄月榜。开启过滤的群只读取全年龄榜，随机取图和作品点图不自动附加另一个榜。
- 日榜自动推送也展示每篇作品的全部分页，通过 `ranking.daily_push` 独立配置，默认关闭。开启后按 `time` 指定的 HH:MM 时间发送，默认 `09:00`，采用全局时区；通过 `groups` 选择接收群。日榜接收群为空时不推送日榜，不影响画师订阅。
- 「榜单变动监测」（`pixiv_push.ranking.monitor`）默认关闭：开启 `enable`，通过 `mode` 选择日榜 `daily`（默认）、周榜 `weekly` 或月榜 `monthly`，并通过群会话选择器选择 `groups`（可多选，留空不推送）。`check_minutes` 默认 30 分钟，建议 1～1440；`pages` 默认 10，范围 1～10，监测榜单前 N 页，每页约 50 部作品。修改设置后重载插件生效。
- 监测在启动或重载时只拉取当前作品 ID 集合建立基线，不发送；之后每轮与上一轮成功获取的集合比较，只推送新加入的 ID。排名变化不推；新增或重新上榜的作品还需检查本群最近成功推送的 200 条 ID，命中就跳过。监测与自动随机发图共用这份历史，成功发送才追加，失败不计入；获取失败不更新基线。同群本轮新增作品的全部分页汇入一条消息，不受 `ranking.count` 限制；允许 R18 的群在日榜／周榜同时监测对应 R18 榜，全年龄内容在前，R18 内容在 NSFW 分割线后。两类榜单分别建立基线，首次启用 R18 监测不会补推整份 R18 榜。推送沿用内容规则、自动翻译、缓存、图片处理和传递方式。各群独立处理发送结果；单部作品下载或渲染失败时保留待重试状态，正常作品仍在本轮合并发送，失败作品不计入成功推送历史。发送失败的作品下轮补试，已掉榜的作品不再补发。榜单基线和各群待发送 ID 仅保存在内存，成功推送的最近 200 条历史沿用 `pixiv_random_history.json` 持久化，重载或重启后继续去重；重启重新建立榜单基线，不补发停机消息。监测与 `ranking.daily_push`、`random_push` 独立开关；日榜定时推送不参与这份历史去重。
- `#pixiv随机` 无关键词时，从多页日榜构建较大的候选池后随机选择，`ranking.pool_pages` 默认 5 页，范围 1～10。带关键词或标签时从搜索结果随机选择，`random.search_pages` 默认 3 页，范围 1～10。`random.count` 默认 1 个作品，范围 1～10，每个作品默认发送全部分页。
- 「随机发图」（`random_push`）默认关闭：配置有效 Pixiv Cookie、开启 `enable` 并通过群会话选择器选择 `groups`（可多选，留空不推送）后，先在 `min_minutes`（下限，默认 1）与 `max_minutes`（上限，默认 120）之间随机等待，再向每个接收群各推送一部随机作品。上下限单位为分钟、均须为正整数且包含端点；可设置超过 120 分钟的上限，相同值表示固定间隔，填反时自动交换，无效值分别回退到默认值。一轮结束后重新抽取等待时间，重载后重新计时，不补发停机期间的消息。候选来自 Pixiv「发现」推荐池，每批请求 60 部作品，过滤后打乱，每批最多检查 12 部作品的实际浏览量，`min_views` 默认 10000，可调整；不是从固定排行榜取图，也不保证对 Pixiv 全站均匀抽样。没有合适作品时继续补取，每群每轮最多请求 5 批（含第一批），连续两批没有本轮未出现过的有效作品 ID 时提前结束；跨批重复 ID 不再检查，找到并成功发送一部就结束。达到上限仍无符合热度和内容规则的作品时跳过本轮；请求或发送失败不立即重试，某群失败不影响其他群。按群排除最近成功推送的 200 部作品（按 Pixiv 作品 ID 去重，同作品所有分页共用一条记录），历史保存到插件数据目录的 `pixiv_random_history.json`，重载或重启后继续生效；各群独立记录，发送失败不计入。某批推荐全部命中历史时会在上述上限内继续补取，耗尽后等待下轮，不清空历史强行重复发送。历史从升级后开始积累，由自动随机推送与榜单变动推送共用。每部作品发送全部分页：全年龄单项直接发送，多项合并转发；R18／R18-G 即使只有单项也使用合并转发；沿用全局及分群的 R18 过滤与展示方式、自动翻译、图片格式兼容处理、压缩阈值和图片传递方式。关闭功能或移除接收群会阻止尚未发送的消息。修改设置后重载插件生效。
- `#pixiv作品 ID或URL` 默认发送作品的全部分页；追加 `第N张` 可只取指定页，例如 `#pixiv作品 https://www.pixiv.net/artworks/123456 第2张`。
- 订阅、榜单、随机和点图统一使用内容规则：全局 `filter_r18` 默认开启，过滤 `xRestrict` 非 0 的作品；同级 `r18_display` 默认 `link`（原图链接），也可选 `image`（原图）。关闭过滤后，R18 作品按所选方式发送真实原图地址或原图，并在作品信息首行按 Pixiv 分级标注 `【R18】` 或 `【R18-G】`，普通作品不加标签；标签在多图作品的信息头部显示一次，不叠加到图片像素上。所有 Pixiv 入口的 R18／R18-G 内容均使用合并转发；若本次仅展示一页 R18／R18-G 图片或一条原图链接，先单独发送 `------- NSFW -------` 提示，再发送该条转发。该提示置于转发外，转发内不重复分割线。任意入口（包括订阅、随机、点图、AI 取图和榜单）的同一条转发中同时包含全年龄及 R18／R18-G 时，统一先展示全年龄，再插入一条 `---------------- NSFW ----------------`，最后展示全部 R18／R18-G；各分组内部保留原作品顺序、排名和分页顺序，不另发外部提示。原图模式只下载原图，不回退到预览图、不按体积阈值缩小；开启格式兼容处理时仍生成 JPEG 发送副本。无法确认分级的作品会跳过。
- 「分群内容规则」（`group_content_rules`）使用与画师订阅相同的群会话选择器，同时覆盖该群的过滤与展示方式。同群匹配多条时只使用第一条；未匹配时沿用全局设置，适用群为空的规则不生效。每条新规则默认开启过滤，展示方式默认为原图链接。
- 按图片展示项数选择发送方式：每张图片或其原图链接均计为 1 项，全年龄内容 1 项直接发送，R18／R18-G 单项及所有 2 项以上内容均合并转发；一张图片加一个原图链接、或两个原图链接也使用合并转发。合并转发需接收平台支持（如 QQ/NapCat）。各入口共用图片缓存及处理流程，优先下载并保留原图，默认生成 JPEG 发送副本；可设置正数体积阈值进一步压缩。单张下载另有 **64 MiB 安全上限**，并非 QQ 大小限制。
- 合并转发按实际展示的作品数组织：仅一部作品时，多张图片或原图链接直接放在同一层转发中；有多部作品时，多图作品才放进内层转发。每部多图作品的第一条消息单独展示作品信息，使用「排名：」「作品名：」「作者名：」「作品链接：」「作品说明：」标签；没有排名或作品说明时省略对应项，说明正文保留全文及换行。后续每条展示一张图片或一个原图链接，开启作品内容翻译时按所选方式展示该图译文；不重复来源文本，也不显示“第几张/共几张”。单图作品直接展示作品信息和图片，不额外嵌套；指定只看某一页时也按单图展示。手动取图、定时榜单和画师订阅共用此结构；Base64 分批时在每批内部按作品分组。
- 作品信息附带 Pixiv 详情接口返回的浏览量、收藏量和点赞量，按千位分隔显示；有效的 0 正常显示，缺失或无效的统计项省略。数据为获取作品详情时的快照，不额外请求统计接口；定时日榜、随机推送、手动取图和画师订阅共用，多图只在作品信息中显示一次。作品信息同时展示画师填写的简介，保留换行和链接。「自动翻译」（`auto_translate.enable`）默认关闭，开启后使用接收群当前的聊天模型翻译作品标题及简介；子配置「翻译语言」（`auto_translate.language`）默认「中文」，留空也使用中文。订阅、定时榜单、随机和点图均生效，每个作品调用一次模型，多图只在来源消息中展示译文。画师姓名、作品链接及图片保持原样；翻译不涉及图片内部的文字。模型不可用、返回异常或单次翻译超过 30 秒时继续发送原文；开启会增加模型用量和等待时间。
- 「作品内容翻译」（`pixiv_push.content_translation`）独立于上述标题、简介的「自动翻译」，`enable` 默认关闭。开启后逐张识别图片内的文字；没有文字时不附译文。画师订阅、手动榜单、日榜自动推送、榜单变动监测、手动随机、随机发图和作品点图等所有 Pixiv 入口均生效。「翻译方式」（`content_translation.mode`）可选「嵌字」（`overlay`）或「纯文本」（`text`），默认纯文本；旧配置未填写此项时继续使用纯文本，在每张图片后附上译文，不修改图片内部文字。
- 选择「嵌字」（`overlay`）后，插件仅调用[百度翻译开放平台图片翻译 API](https://api.fanyi.baidu.com/product/22)。整张图片上传后，由百度云端完成 OCR、翻译和图片渲染，结果另存为发送副本，始终保留下载原图。无需部署本地服务、安装本地翻译模型或配置本地字体。
- 配置步骤：进入[百度翻译开放平台图片翻译](https://api.fanyi.baidu.com/product/22)，按平台要求创建应用并开通「图片翻译」，取得应用的 **AppID** 和 **密钥**；在「作品内容翻译」中开启 `enable`、将「翻译方式」选为「嵌字」，再于「百度图片翻译」（`content_translation.typesetting`）填写 `app_id` 和 `app_key`。两项默认均为空，密钥以敏感字段展示。这里使用百度翻译开放平台的凭据，不是百度智能云的 APIKey / SecretKey，也不是 DeepSeek API Key。旧的服务地址和翻译器配置已移除，不再读取。
- 百度图片翻译输入须为不超过 **4 MiB** 的 PNG / JPEG 图片。插件上传下载到的原图，不为满足接口限制而在本地压缩、缩放或转换；超出体积或格式限制、凭据缺失、权限未开通、接口不可达、响应异常或处理超时时，继续发送原图并提示「翻译暂不可用」。嵌字失败不改为纯文本翻译。费用和免费额度由百度官方账户、服务套餐及当时规则决定，插件不保证免费；每张未命中缓存且成功处理的图片都会计入官方图片翻译用量。已验证的成功结果缓存可直接复用，不再请求百度；缓存失效或原图、语言等条件改变后可能重新调用。
- 内容翻译的「内容翻译识图模型」（`content_translation.provider_id`）仅用于纯文本模式和 R18 原图链接的文字翻译，可通过模型选择器指定，留空使用接收群当前的聊天模型；所用模型需要支持图片输入。嵌字不使用此模型。「翻译语言」（`content_translation.language`）默认「中文」，留空也使用中文，与标题、简介的翻译语言分别配置。嵌字时插件将支持的语言名称或代码映射为百度目标语言代码，例如中文／`zh`、繁体中文／`cht`、英语／`en`、日语／`jp`；不支持的语言会按翻译不可用处理，不提交百度请求。「单页处理超时」（`content_translation.timeout_seconds`）默认 120 秒，可设置 30–300 秒，纯文本与嵌字共用；旧配置未填写也使用 120 秒。云端处理较慢时可尝试 180 秒；延长超时会增加持续无响应时的等待，接口自身的更短超时仍可能提前中断。模型不可用、超时或翻译失败时提示「翻译暂不可用」，并继续发送原图。
- 所有 Pixiv 入口使用「共享处理池并发上限」（`pixiv_push.processing_concurrency`），默认 10，范围 1–32；旧配置未填写时同样使用 10，修改后重载插件生效。同一模块实例的所有群、作品和分页共用这个上限，不按群数叠加：作品分页准备与标题／简介翻译、各页下载与内容翻译／嵌字都占用共享处理名额。网络请求异步执行，完成先后不同，消息仍按原始作品及页序组装，全部页处理完后才发送。百度图片翻译另有同一实例最多 **1 个并发请求**的限制，与共享处理池独立，所有群和入口共用。单页超时从获得共享处理名额并完成下载后开始，包含等待百度图片翻译名额及云端处理时间，不含共享处理池排队和图片下载。并发不减少调用次数，也不加快单次处理。取消或必要图片下载失败时会取消并等待其余页面协程清理；HTTP 请求超时或取消不保证云端停止正在运行的任务，插件不会自动重试，避免重复提交。
- R18 采用「原图链接」展示时始终发送原图链接，并在对应链接后附上可用的纯文本译文，即使选择嵌字也不发送嵌字副本，避免绕过该群的展示策略。开启作品内容翻译仍会下载原图并交给模型识别，即使最终只展示链接也会产生图片下载和模型调用。
- 「图片传递方式」（`image_transport`）默认 `file`（本地文件）：只发送图片的绝对文件 URI，协议端直接读取缓存，多图保持一条合并转发，保留全部图片、作品信息及分页顺序，单图仍直发。AstrBot 与协议端须共用文件系统，协议端进程必须有权限读取这些文件；不同容器需挂载相同路径，否则选择 `base64`。手动取图、榜单定时推送和画师订阅共用此设置。
- Base64 模式通常按编码后的估算体积分批合并转发，每批目标不超过 16 MiB，单项超过目标体积时独立成批；保留全部图片和分页顺序，使用与文件方式相同的发送副本，分批不额外压缩图片。双榜、榜单监测及任意入口的全年龄／R18 混合内容按单条消息要求合并，不进行这种分批，仍受协议端请求大小限制；较大榜单建议使用本地文件方式或减少榜单数量／监测页数。
- 图片缓存默认保留 7 天，`cache_retention_days` 可调整，设为 0 关闭自动清理。`cache_cleanup_time` 默认 `00:00`，每天按全局时区执行，修改时间后重载插件生效。按文件最后修改时间判断是否已保存满指定天数，清理原图、预览图、压缩版、遗留临时文件及空目录，不删除订阅进度。图片被清理后再次取图会重新下载。
- 「图片格式兼容处理」（`image_format_compatibility`）默认开启：静态图片生成 JPEG 发送副本，质量参数 90、保留尺寸（EXIF 方向转正时宽高相应交换），透明区域铺白。多帧图片保留原格式，不转换成静态图。手动取图、定时推送、文件和 Base64 方式均生效。副本按原图内容和体积阈值缓存，重复发送直接复用；已有原图缓存无需重新下载。关闭后沿用原始格式，仅在超过正数体积阈值时压缩。
- `max_image_mb=0` 表示不限制体积，格式兼容处理仍会生成 JPEG 副本；正数阈值会在需要时进一步降低质量或缩小尺寸。兼容处理开启时，多帧图片超过正数阈值会跳过，避免静默丢帧。图片校验和转换各最多等待 30 秒，超时则本次取图或推送失败；关闭兼容且无需压缩时仅校验文件结构，不完整解码像素。
- 手动取图的合并转发使用当前消息中的机器人账号；定时推送按配置的目标群发送，与日报共用框架发送接口，节点账号优先从该平台当前的 OneBot 连接读取，无需先发送群消息，重启后连接建立即可使用。连接未提供具体账号时才查询并缓存登录信息，查询最多等待 10 秒。
- 手动取图在发送阶段报错时，会尝试发送一条文字提示；协议端超时会提示「尚未确认送达」，避免把缺少成功回执直接当作未发送。提示消息本身最多等待 10 秒，发送失败仍记录日志。不会自动重发图片；请先检查实际接收情况，避免重复消息。画师订阅仍仅在框架确认发送成功后推进进度。
- 可选填写敏感配置 `cookie`：只需输入 Pixiv Cookie 中 `PHPSESSID` 的值，无需添加 `PHPSESSID=` 前缀；也兼容原先的完整 Cookie。默认留空，以未登录方式访问；凭据不在消息中回显。
- 开启 Pixiv「打印日志」时，启动或重载后会在后台校验一次登录状态：`Pixiv login: valid` 表示登录有效，`Cookie invalid` 表示凭据无效，`network error; status undetermined` 表示网络异常、暂无法判断；服务器拒绝或响应异常则记录 `unexpected server response; status undetermined`。未填写时记录使用未登录请求；关闭日志则跳过校验。校验不阻塞启动、不影响榜单或订阅，日志不包含凭据或响应正文。
- 随机发图在每次抽取间隔后记录 `Pixiv random push scheduled`，包含下次任务时间 `next`（按全局时区显示并带 UTC 偏移）和等待分钟数 `wait_minutes`；等待结束后记录 `Pixiv random push triggered`，表示开始筛选和推送，实际送达时间还取决于下载、处理与发送耗时。这两条日志遵循 Pixiv「打印日志」开关，关闭随机发图后不再打印。日榜自动推送开始处理时也记录 `Pixiv daily ranking push triggered`，同样遵循日志开关。
- 访问 Pixiv 需代理时，在「全局设置 → 网络代理」填写 HTTP 代理地址。配置后，Pixiv API 与图片域名由该代理解析，兼容 Clash 的域名规则及本机 DNS 异常；未配置时仍直接访问。
- 画师订阅获取作品、下载或发送失败时，默认依次等待 2、4、6…分钟；基础间隔可调，成功后恢复正常检查。任务按分钟调度，实际可能略晚。

**全局设置**：网络代理填写 HTTP 地址，例如 `http://127.0.0.1:7890`；时区默认 `Asia/Shanghai`。详细日志默认开启，可按需关闭。

## 常见问题

### 日报或帮助图的中文显示为方框

在 **AstrBot 实际运行的系统或容器**中安装中文字体，按系统选择命令。

Ubuntu / Debian：

```bash
sudo apt-get update
sudo apt-get install -y fontconfig fonts-noto-cjk
```

Rocky / AlmaLinux / RHEL 8、9 等 dnf 系统：

```bash
sudo dnf install -y fontconfig google-noto-sans-cjk-ttc-fonts google-noto-serif-cjk-ttc-fonts
```

刷新并确认字体：

```bash
sudo fc-cache -f
fc-list :lang=zh family
```

应能看到 Noto Sans CJK 和 Noto Serif CJK。其他 dnf 发行版的包名可能不同，可用 `dnf list --available '*noto*cjk*'` 查询。

安装后重启 AstrBot。日报还需备份移走 `data/plugin_data/astrbot_plugin_juhkff/daily_report/YYYY-MM-DD/` 下当天的五张样式 PNG，再发送 `#日报`；保留新闻快照和配图即可。帮助图每次重新生成，无需清理。

### 设置代理后仍无法访问 Pixiv

- 代理必须能被 AstrBot 所在环境访问。Docker 中的 `127.0.0.1` 指向容器自身；仅提供 SOCKS5 的地址不能直接使用。
- 插件代理用于网页和图片请求，模型 API、QQ 连接按各自配置处理。
- 本机 DNS 仍需返回真实公网地址；代理的 Fake-IP 模式可能被安全校验拒绝。网络请求仅允许公网 HTTP(S) 的 80/443 端口。

### 数据保存在哪里

- 订阅等设置：`data/config/astrbot_plugin_juhkff_config.json`。
- 表情、日报和 Pixiv 缓存：`data/plugin_data/astrbot_plugin_juhkff/`。备份迁移时可一并保留该目录和配置文件。

## 开发与测试

在已安装依赖的 AstrBot Python 环境中，从 **AstrBot 根目录**执行：

```bash
PYTHONPATH=.:data/plugins/astrbot_plugin_juhkff \
  python -m unittest discover -s data/plugins/astrbot_plugin_juhkff/tests -p 'test_*.py'
PYTHONPATH=. python data/plugins/astrbot_plugin_juhkff/tests/check_command_routing.py
```

第二条独立运行，以隔离插件入口的热重载注册。测试覆盖网络安全、卡片、表情、渲染、缓存、Pixiv 状态及命令分发，不调用真实模型或发送群消息。
